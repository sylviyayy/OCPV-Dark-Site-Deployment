## Part A — Network

### WHERE: Switch A and Switch B (configure before powering cluster nodes)

### Step 1 — Port-channels (matches physical cabling)

**WHAT:** On each switch, create LACP port-channel (e.g. `Po1`, `Po2`) and assign server ports as members.

**WHY:** Must match server-side `bond0` mode `802.3ad`. Mismatch = bond stays down.

**FAILS IF:** Access port on wrong VLAN or Po not on both switches.

### Step 2 — VLAN strategy

| Profile | Machine network | BMC | Storage |
|---|---|---|---|
| **Lab (simplest)** | Flat L2, no tags | Separate mgmt subnet | Same flat or dedicated |
| **Enterprise** | VLAN 10 | VLAN 99 | VLAN 30 (iSCSI) |

This repo’s default templates use **flat L2** for CoE labs. Document VLAN IDs in the worksheet when upgrading to enterprise.

### Step 3 — VIPs (layer 3)

**WHERE:** Routed on install subnet — often static ARP or keepalived on nodes; Agent-based bare metal uses `apiVIPs` / `ingressVIPs` in `install-config.yaml`.

| VIP | Example | Purpose |
|---|---|---|
| API | `10.10.0.100` | `oc login`, kubeconfig |
| Ingress | `10.10.0.101` | `*.apps` routes |

**WHY:** No external load balancer required with Agent-based Installer on bare metal.

**FAILS IF:** VIPs not reachable from bastion and all nodes during install.

### Step 4 — Node L3 (agent-config / nmstate)

**WHERE:** `install-config/agent-config.yaml` on bastion (generated by `scripts/03`).

**WHAT:** Per host: bond0, static IP, DNS → bastion, default route → gateway.

**WHY:** No DHCP in dark site.

Templates: [install-config/agent-config.yaml.template](../../install-config/agent-config.yaml.template)  
IP tables: [02-network-design.md](../02-network-design.md)

## Part B — Storage

### WHERE: SAN admin console + each node initiator

### Step 1 — OS disk (local)

| Setting | Value |
|---|---|
| RAID | RAID1 (2 SSDs) |
| Presented device | `/dev/sda` (verify per vendor) |
| Scope | RHCOS only |

### Step 2 — OCP data LUN(s)

**WHAT:** Create LUN on SAN; size per Red Hat / partner sizing guide for CoE.

**WHY:** Persistent volumes for OCP-V VM disks (via CSI / LVMS / NFS — chosen at platform layer).

### Step 3 — LUN masking

**WHAT:** Present LUN only to IQN/WWN of **cluster nodes** in the worksheet.

**WHY:** Prevents non-cluster hosts from accessing data; prevents accidental double-mount.

**FAILS IF:** Masking too broad → security risk; too narrow → PV mount failures.

### Step 4 — Multipath on nodes

**WHERE:** Validated after RHCOS boot (post-install); paths must exist at hardware level now.

**WHAT:** Two independent paths from node to SAN (diagram: HBA1/HBA2 or dual subnet iSCSI).
