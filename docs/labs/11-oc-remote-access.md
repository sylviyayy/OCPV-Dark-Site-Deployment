# 11 — Configuring `oc` for Remote Access

## Goal

Use `oc` / `kubectl` from the jumpbox (and optionally your laptop) against the API VIP.

## WHERE

Jumpbox (and any admin workstation that can reach `API_VIP`).

## WHY

Hard Way’s “configure kubectl” lab. Here the kubeconfig is generated by the installer.

## DO

```bash
export KUBECONFIG="${PWD}/install-config/auth/kubeconfig"
# Persist for your shell profile if desired:
mkdir -p ~/.kube
cp install-config/auth/kubeconfig ~/.kube/config
chmod 600 ~/.kube/config

oc whoami
oc get nodes
oc get co
```

From another machine, copy `kubeconfig` securely (never commit it) and ensure DNS or
`/etc/hosts` resolves `api.<cluster>.<domain>` to `API_VIP`, **or** use

```bash
oc login --server=https://<API_VIP>:6443 --kubeconfig=...
```

(API certs expect the API hostname — prefer proper DNS from Lab 07.)

## VERIFY

```bash
oc cluster-info
oc get projects
```
